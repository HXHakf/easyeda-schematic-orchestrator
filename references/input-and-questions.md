# 按电路类型补问

先判断实际设计意图和电路类型；未知类型先问要实现什么功能，不直接套 MCU+传感器问卷。

| 类型 | 核心字段 | 条件字段 |
|---|---|---|
| MCU 最小系统 | MCU 完整型号、输入、供电来源、逻辑电压 | 晶振频率、调试接口；明确要求 I2C 才问上拉 |
| MCU + 传感器 | MCU/传感器型号、传感器形态、供电、接口 | 模块已有上拉、快速模式电容、晶振 |
| LDO 电源 | 输入/输出电压、最大负载电流、供电来源、LDO 型号 | 具体型号的压差、稳定性电容、输入范围和热约束，由资料与 unresolved 补齐 |
| 其他电路 | 功能与明确约束 | 宿主模型依据功能补充约束和 unresolved |

每次 assess 同时返回 questions（全部阻断项）与 next_questions（优先的至多三项）。
可自行查证的手册、文档路径与资料摘录缺项先转为宿主检索、下载或阅读任务，补齐后重新 assess。
面向用户只问需要用户决定的下一轮关键问题，已有答案不重复问。接口输出 ready=true 只说明已结构化字段无阻断，
不证明型号、封装、拓扑或器件适用性正确；semantic_review_required 始终保留。

用户可以说“帮我选”。用 update 把该字段转为 selection_requests，模型收到 selection_tasks，
根据用途/精度/负载/成本等约束查证候选并填入准确型号与依据；此时 ready 仍为 false。
不能把“帮我选”当准确型号，也不能再次只问型号而忽略选型任务。

## 官方手册与应用电路

具体项目优先采用用户所选模块的官方数据手册，重点读取 Typical Application、Application Circuit、
Reference Schematic 等应用电路章节。先核对模块身份、厂商和版本，再以匹配需求的官方电路作为起点。

- 用户已提供手册时，先核对其型号、封装或模块版本；用户只提供型号时，宿主自行检索厂商官网、
  产品页和官方文档入口，下载对应手册并填写内部资料清单的本地路径。型号不足以定位资料时先澄清模块身份。
- 下载文件保存到项目私有资料目录，例如 `runs/<project>/documents`，记录实际来源 URL、文档版本和内容哈希。
  复用已有同内容手册和审阅记录，文件位置与文档身份按现有资料缓存规则管理。
- 官方文件暂不可取得时，继续查询厂商参考设计、应用笔记或可信分销渠道的原厂文档，核对出处、型号与版本。
  资料冲突及缺项按当前项目的资料核验流程处理。
- 阅读应用电路图本身，并结合引脚表、工作条件、器件取值说明、可选支路和脚注核对连接。
  PDF 中的图形使用可用的图页查看或渲染能力审阅。记录章节、PDF 页码或印刷页码及图号，并区分页码体系。
- 选用成品模块时，先核对模块厂商的接线图、接口定义和板载外围，再用内部芯片手册补充相关依据。
  核实已集成的上拉、去耦、稳压和保护元件后，再决定新增外围。
- 根据项目需求调整供电、接口、使能或复位、外围参数及可选器件，逐项记录官方连接或取值、
  本次采用方案和调整理由。通用知识卡补充连接方法、计算与错误检查，项目方案以所选模块的官方资料核验。

手册未给出应用电路图时，优先引用同厂官方参考设计或应用笔记，并标明实际使用的依据。
资料获取与图页审阅由宿主完成。现有 Python 检查资料身份、内容哈希、结构及已编码规则。
内置模板与知识卡先对照官方电路的适用条件使用，超出模板支持范围时沿用宿主编写 plan 和 validate-plan 入口。
设计确认与计划中的记录方式见[用户确认与内部版本](design-contract.md)。

## 多轮修改与默认值

默认值保存 depends_on 条件。再次 assess 时先撤销仍属推断的旧值，再按当前条件重新计算。
例如裸芯片改为模块，撤销默认新增上拉和默认阻值，重新确认模块是否已有上拉；3.3V 输入改5V，
撤销自动推断的逻辑电压。用户主动指定的值保留，冲突则明确报告。

用 update 合并回答，显式回答会取消该字段的默认身份；即使重新确认的数值与原默认相同也有效。
切换电路类型时清理旧类型专属字段，保留本轮新给出的字段与公共供电/约束。

intake 仍是保守种子解析器，宿主模型复核否定、多个电源域、实际测量功能及其他约束。
例如温湿度需求不能自动选不测湿度的 BMP280。未解决的功能或电气问题写入 unresolved 并阻断确认。

真正执行时再绑定获准测试工程/页面；只做需求、方案或开发工作流时不强求连接 EDA。
