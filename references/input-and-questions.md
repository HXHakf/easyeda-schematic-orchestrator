# 按电路类型补问

先判断实际设计意图和电路类型；未知类型先问要实现什么功能，不直接套 MCU+传感器问卷。

| 类型 | 核心字段 | 条件字段 |
|---|---|---|
| MCU 最小系统 | MCU 完整型号、输入、供电来源、逻辑电压 | 晶振频率、调试接口；明确要求 I2C 才问上拉 |
| MCU + 传感器 | MCU/传感器型号、传感器形态、供电、接口 | 模块已有上拉、快速模式电容、晶振 |
| LDO 电源 | 输入/输出电压、最大负载电流、供电来源、LDO 型号 | 具体型号的压差、稳定性电容、输入范围和热约束，由资料与 unresolved 补齐 |
| 其他电路 | 功能与明确约束 | 宿主模型依据功能补充约束和 unresolved |

每次 assess 同时返回 questions（全部阻断项）与 next_questions（优先的至多三项）。
面向用户只问下一轮关键问题，已有答案不重复问。接口输出 ready=true 只说明已结构化字段无阻断，
不证明型号、封装、拓扑或器件适用性正确；semantic_review_required 始终保留。

用户可以说“帮我选”。用 update 把该字段转为 selection_requests，模型收到 selection_tasks，
根据用途/精度/负载/成本等约束查证候选并填入准确型号与依据；此时 ready 仍为 false。
不能把“帮我选”当准确型号，也不能再次只问型号而忽略选型任务。

## 多轮修改与默认值

默认值保存 depends_on 条件。再次 assess 时先撤销仍属推断的旧值，再按当前条件重新计算。
例如裸芯片改为模块，撤销默认新增上拉和默认阻值，重新确认模块是否已有上拉；3.3V 输入改5V，
撤销自动推断的逻辑电压。用户主动指定的值保留，冲突则明确报告。

用 update 合并回答，显式回答会取消该字段的默认身份；即使重新确认的数值与原默认相同也有效。
切换电路类型时清理旧类型专属字段，保留本轮新给出的字段与公共供电/约束。

intake 仍是保守种子解析器，宿主模型复核否定、多个电源域、实际测量功能及其他约束。
例如温湿度需求不能自动选不测湿度的 BMP280。未解决的功能或电气问题写入 unresolved 并阻断确认。

真正执行时再绑定获准测试工程/页面；只做需求、方案或开发工作流时不强求连接 EDA。
