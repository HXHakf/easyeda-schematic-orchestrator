# 现场问题复盘与恢复

本页维护 ESO 现场问题的判断与处理入口。先按症状定位，详细操作沿用已有参考。
软件修复、宿主操作和现场验收的覆盖范围分别记录，具体历史结果见
[开关验收](../docs/plans/npn-nmos-eda-acceptance.md) 与
[MCU 组合验收](../docs/plans/mcu-switch-eda-acceptance.md)。

## 按症状定位

| 症状或任务 | 先查什么 | 处理入口 |
|---|---|---|
| 工具已更新，仍报 class inventory 或连接器能力缺失 | 实际加载版本、目标窗口、原始快照及编译回执 | [环境与诊断](#环境与诊断) |
| doctor 对已有图纸报替换编译失败 | 页面是否已占用，探针适用范围 | [环境与诊断](#环境与诊断) |
| ATTRMATCHCODE，或补商品属性后身份对账失败 | 精确料号对应的全部目录条目及原生来源证明 | [目录身份](#目录身份) |
| Apply 失败，但页面已有器件或接线 | 新鲜库存、原队列及 journal 已落地步骤 | [放置与执行恢复](#放置与执行恢复) |
| 模块可布局，整页却放不进 A4 | 模块包络、全文字、图签禁入区和装箱失败 | [布局搜索与整页方案](#布局搜索与整页方案) |
| 更新姿态后位号移位，原生检查通过但图面重叠 | 写入后的完整属性及新 SVG 字体实测 | [文字与图签](#文字与图签) |
| 图签坐标为 null、保存重开后属性 ID 重建，或旋转文字 bbox 不符 | 原始属性、稳定归属及 SVG 校准 | [文字与图签](#文字与图签) |
| 模块标签被 strict 拒绝，或经验距离导致无效返工 | 模块内物理树、标签附着及规则原文的适用范围 | [规范与审计](#规范与审计) |
| 一项检查通过，其他报告仍有未覆盖项 | 每份报告的实际对象、输入版本、工具覆盖及宿主修复 | [验收与证据](#验收与证据) |
| 手册能找到参数，但完整工作条件无法证明 | 事实、推导包络和当前工程条件 | [依据与效率](#依据与效率) |
| PowerShell 引号、编码或回执解析异常 | 实际 argv、stdout/stderr 和退出码字段 | [下层调用与测量指南](../extras/schematic-verified-layout/references/live-recovery.md#判据测量与证据) |

## 环境与诊断

磁盘上的 CLI/Skill 更新后，编辑器可能仍加载旧 Connector。记录 CLI、daemon、Skill 和加载态
Connector，使用 health 定位精确工程、页面及窗口，再核对实际 help/schema 和原始快照。
v1.16.0 的十类/十一类快照问题由写前 compose/dry-run 复现，版本相同也需要能力检查。
连接器安装、重载和 ownerType 探测沿用[下层恢复指南](../extras/schematic-verified-layout/references/live-recovery.md#写前预检与顺序)。

`doctor --live` 分别报告连接、版本、快照、合成编译探针和指定目标的历史验收。
合成替换探针只适用于已证明空白的页面。已有器件、文字或归属不明属性时，该项应为 `not_checked`，
实际方案的编译能力由对应 prepare/compose/dry-run 证据说明。历史验收成功仍保留
`fresh_readback=false`，当前设计验收另行运行 verify。

覆盖见 [doctor 正反测试](../tests/test_knowledge_tools.py)。维护和诊断保持只读，连接器恢复按上游支持的生命周期接口执行。

## 目录身份

同一精确 C 号存在通用条目与完整厂商条目时，在放置前完成精确搜索和 device get，优先选取
身份资料完整且与选型一致的条目。核对制造商、完整 MPN、Supplier、封装、原始 symbol/footprint
及全部物理脚，保留原始查询和绑定依据。

本轮通用接口补齐厂商字段后，DRC 曾通过，canonical 来源证明却丢失。属性修正后要同时检查
DRC 和库身份/逐脚对账。任一失败时先保留回读，调查完整目录条目及来源关系。
同 C 号本身不足以证明等价。确需重新绑定时，记录前后库身份、物理映射和确认影响。

同一已选器件的库身份解析可在现有授权内完成，旧运行包继续保留。更换影响契约的型号、封装、引脚、条件
或目标时，沿用[确认失效规则](design-contract.md)。v2 已固定资料或库依赖变化时，按
[v2 证据规则](knowledge-v2.md)重新核验和确认。不能把本次保留通用契约的个例扩展到所有换库操作。

device 字段投影和组件 lineage 的处理沿用[商品属性与身份](../extras/schematic-verified-layout/references/live-recovery.md#商品属性与身份)。

## 放置与执行恢复

失败后保留原队列、返回、journal 和锁，先读取当前状态，再决定恢复阶段。

| 当前状态 | 可用路径 | 恢复后证据 |
|---|---|---|
| 归属明确、尚未接线的初始放置 | `recover-stage` 输出到新目录，已存在实例保留，只为缺件生成 canonical 子集 | 原实例、缺件清单、完整恢复历史及独立保存回执 |
| 已有接线、标签或 NC | 从实际差异形成受保护修订，按[部分 Apply 指南](../extras/schematic-verified-layout/references/live-recovery.md#部分-apply-与假失败)处理 | 新基线、局部操作范围、前后对账及完整复验 |
| 存在未知实例、归属不明或证据不完整 | 保留错误及当前快照，先补齐来源与状态 | 来源明确后重新判断恢复路径 |

v1.17.0 放置 journal 可能省略 `doc`。现有恢复器通过原队列的字节哈希及精确 project/doc
核对目标，显式错误页面仍拒绝。原始日志保持原样。连续恢复需携带全部祖先队列、日志和恢复清单，
prepare 将这些副本固定到执行摘要。接口与命令见[初始放置恢复](measurement-bridge.md#初始放置恢复)，
正反覆盖见[恢复测试](../tests/test_recovery.py)及[衔接测试](../tests/test_bridge.py)。

现场已验证完整未接线库存的恢复，保留全部实例且新增放置为零。真实缺件补放正例仍待验收，
模拟及离线成功按各自范围报告。

## 布局搜索与整页方案

局部模块布局成功后，还要检查整页装箱。本轮自动展开造成模块包络过大，增大搜索预算仍未得到适用的 A4 方案。
先区分资料/身份/测量缺项、模块几何搜索和整页装箱失败，再选择调整对象。

- 固定真实器件姿态、全部可见文字、纸张和图签禁入区，检查外围归属、旋转自由度、模块包络及间距。
- 保留合法候选与失败原因，按明确预算比较有针对性的变体。没有改善证据时改变几何策略，记录停止原因。
- 宿主修订 composition 时，从原始测量生成独立派生源，记录偏移、旋转、路径和模块变化。新库绑定或文字变化后重新测量。
- 使用现有上游布局、装箱和 compose 校验完整整页，固定方案通过 `prepare --layout-page` 复制并纳入摘要。
  继续通过已安装的 typed CLI 执行。

具体接口见[已选整页几何](measurement-bridge.md#已选整页几何)。本轮隔离上游离线实验用于诊断和候选验证，
宿主修源仍是人工介入。公开指南保留通用处理方法，样例坐标与临时工具留在私有证据中。

## 文字与图签

保留实例的姿态/位置更新和商品属性写入都可能重置文字 XY。最终位号、型号和元数据确定后安排文字，
写入后重新读取完整 raw 属性及官方 SVG，检查位号、型号与符号边框、线路、模块框和图签的净空。
本轮补充审计发现的轻微边框重叠也纳入修正和重导复查。

恢复文字位置前先核对实际器件、实例及连接。根据已实测的原偏移和当前器件位置计算新位置，使用当前
owner + Key 对应的属性和完整 expected raw 状态，仅修改声明的坐标。随后重新保存、重开、采集并复验。
每个符号的文字净空由实测决定，本轮使用的偏移量留在样例记录中。

图签 null 坐标初始化、属性 ID 重建、公式/null/缺字段的语义保全，以及旋转 bbox 校准沿用
[下层变更与对账指南](../extras/schematic-verified-layout/references/live-recovery.md#变更使哪些证据失效)。

## 规范与审计

嘉立创继续作为[统一规范入口](schematic-design-rules.md)的核心来源。已有条目复用其 ID 和细则。
`3g` 在配套 G3 中用于初始排布参考，最终按真实符号、外围归属、连接路径和文字净空审阅。
框间空带、短引脚出线等已有机器阈值仍按其定义执行。

跨模块采用标签边界时，每个参与模块内该信号网应保持一棵完整物理树，每棵树都有匹配的附着标签。
模块内断线、缺少一侧标签、direct 组及跨模块实体线分别检查。规则定义和正反例见
[可读性门](../extras/schematic-verified-layout/references/readability-gate.md)及
[审计测试](../extras/schematic-verified-layout/tests/test_readability_audit.py)。

组合审计从完整 plan 和新鲜快照生成 target/scene，覆盖全部模块、器件、物理脚、真实 NC、模块框及标题。
单模块样例的空 NC 或单框假设须按当前设计重新构建。原生 SVG 中的外部文字、符号内部引脚注释和固定图签印字
按对象归属分类，记录各自覆盖方式。未纳入外部碰撞检查的内部文字仍需图面审阅。

## 验收与证据

最终使用同一修订保存重开后的新鲜快照和官方导图，关联原生检查、补充 target/scene/strict 审计与图面审阅。
宿主修正后重跑受影响检查，旧失败及旧导图保留。原生检查通过后仍需检查其覆盖之外的边框、文字和阅读路径。

`verify`、`deliver`、独立图面报告及原生工程导出各有覆盖范围，按
[交付证据组织](verification.md#交付证据组织)关联文件摘要与未覆盖项。
core manifest 中仍列出 visual export review 时，引用独立图面报告说明补充结果，保留原报告原文。
当前没有自动合并全部报告的总验收器。

0.5.0.dev8 起，verify 按 attempt 保存独立输入、原始回执及最终快照，正常写入/复验入口使用同一目标锁。
目录核验、实测文字恢复、布局候选比较及补充验收索引见[辅助工具](workflow-assistance.md)。
旧历史原始文件缺失时需从留存证据核对，具体阶段状态见[深入审查](../docs/plans/workflow-improvement-review.md)。

工程导出前查询当前 help 和目标窗口。当前 v1.17.0 的 project export 实测需要显式 window 和 project UUID，
导出后检查文件与归档 CRC。官方 SVG 可经隔离浏览器生成预览，证据记录渲染方式。
屏幕采集不可用时如实记录该限制。绘图、截图、仿真、PCB 和实物的结论按实际检查分别报告。

## 依据与效率

真实资料应先分为手册事实、带适用条件的推导、当前工程计算。典型值或单个测试点无法覆盖声明工况时，
保持缺项或 draft，严格知识库消费者继续阻断。若用户另行同意工程假设下的 EDA 测试，在契约中明确范围，
交付保留该假设及未验证的电气条件。资料状态与具体缺项见
[真实资料检查](../docs/plans/knowledge-real-material-feasibility.md)。

把资料缺项、目录身份和工作条件检查前移到放置前，减少先画后换库的返工。对同一问题先查询本页与既有日志，
复用已验证处理路径。记录每次失败/恢复的阶段、原因、输入与工具版本、实际动作、证据文件和复验结果，
遇到新问题就在对应小节补充触发条件和处理依据。

效率测量沿用既有 metrics 结构，记录成功与阻断任务、补参和资料整理次数、分阶段耗时，人工等待与工具时间分开。
当前三次资料导入记录止于草稿阻断，完整首次设计、跨工程复用和修改工况对照仍待完成。
