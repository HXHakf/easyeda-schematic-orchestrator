# 画法语法：正面构图标准（O1–O8 / HR 条款的 EasyEDA 版，含模块化硬门）

本文件回答「线接对之后，怎么摆才读得懂」。它不替代 [数据格式](audit-data.md) 的电气对账，
也不替代 [可读性门](readability-gate.md) 的判定；它是摆件与走线时的**正面规则**。
其中 G0（模块化布局）是硬要求，不是风格建议。

同一张网表可以有零交叉版和 29 处交叉版（100W 充电器页实测：重画前 29 交叉/237 拐弯，
从引脚出发重画后 0 交叉/82 拐弯）。可读性不是审美偏好，是交付标准。

标注约定：**[检查]** = `readability_audit.py` 能确定性判定；**[审阅]** = 只能在渲染图上追路径；
**[两者]** = 检查器抓明显违例，审阅抓语义错误。

## 0. 先定栅格与单位

- 从 `sch list --include-pins` 实测的引脚坐标求 `g = gcd(所有共线最小间距)`，写进 scene.json 的 `grid`。
  不要用「大概 2.54mm」代替实测；EasyEDA 原始单位与 mm 的换算按当前库实测确认一次。
- 坐标 y-UP（与上游契约一致）。所有间距以 g 为单位表达，便于换库/换页复用。
- 经验区间：局部出线 ≥2g；同组器件间距 2–4g；组间 ≥2 倍组内；单页最远相关器件 ≤12g（≈15mm 量级），
  超出必须在交付说明里写理由。
- 引脚到符号的距离沿用上游：pin→power netflag 20–40、pin→GND 10–40、pin→netport 20–60、
  pin→信号 netlabel 中位 30（raw units）。这些是「真实短桩」，不是可省的长度。

## G0 模块化布局是硬要求 **[检查]+[审阅]**

模块不是「分几块放」的建议，而是可判定的硬门：每个功能模块有自己的区域、标题与内部走线，
模块之间只通过电源符号和标签/netport 交接，绝不用一根连续导线穿过去。

- 目标文件 `modules` 必须覆盖每个器件且只覆盖一次；`core` 写决定该模块功能的那几个器件，
  `direct` 写同模块内必须实体直连的组。
- 模块归属直接来自 `modules`，所以无论有没有画框，这两条都始终检查：
  - `module-physical-crossing`（hard）：同一物理连通树里出现 ≥2 个模块的引脚 = 模块边界被连续导线穿透。
    跨模块只准标签/netport；GND 也要在每个模块内各自用符号落地，不要一根 GND 横穿全页。
  - `module-split-pages`（hard）：同一模块的引脚分散在多页——该拆的是页，不是模块。
- scene.json 再声明 `moduleFrames: [{moduleId, page, bbox:[minX,minY,maxX,maxY], titleTextId?}]` 后，加上框规则：
  - `module-out-of-frame`（hard）：模块的引脚、body、文字或本模块导线任一越出自己的框。
  - `module-overlap`（hard）：两块框相交或相切；框与框之间必须有留白。
  - `module-frame-missing`（hard）：有引脚的模块没有声明框。
  - `module-gutter`（advisory）：框间距 < `--min-module-gutter-grid`×g（默认 4g）。空带就是读者
    区分模块的视觉边界，不是浪费面积。
  - `module-title-missing`（advisory）：模块没有标题文字，或标题不在框内。
- 不声明 `moduleFrames` 时框规则跳过并记为未验证；模块边界与跨页两条仍然拦人。
- 框用 EasyEDA 的分区/矩形图元画（外框 + 左上角标题），不要拿 wire 画框，否则会进网表。
- 模块内部仍要遵守 G1–G8：模块化不豁免交叉、折弯与间距规则。
- **[审阅]** 框线不得穿过模块外的信号；标题要兑现该模块的读者任务；同页模块按信号流或供电层级排列
  （电源在左/上、负载在右/下），读者不应在框之间来回跳。

## G1 页面任务与流向 **[审阅]**

- 分页前先写一句**读者任务**：本页回答什么问题（某接口全貌 / 主电源路径 / 控制器与外设）。
  写不出一句话的页，是还没想清楚，不是「再挤一挤」。
- **路径页**（信号或功率从 A 到 B）：主路径占一行，左→右，主干 y 不变；第二条独立路径另起一行，
  不共用行。支流按方向分出：电源向上、地向下。
- **控制器页**：MCU/核心 IC 居中，电源脚朝上/下，输入侧朝左、输出侧朝右；支持电路贴对应引脚组；
  对外接口/连接器靠页边，扇出顺序从中到外，先直后折。
- 一页一个主张。电源、MCU、模拟前端、连接器全塞一页，等于没有主张。
- 主干方向单页最多两个（横/竖择一为主）；禁止主干交叉。

## G2 锚点：三脚及以上器件与连接器先放 **[审阅]**

- 先放 IC、连接器、电感/晶振等「锚点」，尽量正立；只为准入朝上游、输出朝下游才旋转。
- 元件朝向由**导线方向**决定：先定走线方向，再选旋转角；不要先转好再强行拉线回头。
- 多引脚 IC 的引脚组决定支持电路位置：去耦/滤波跟着电源脚，分压/定时/补偿/检流跟着各自功能脚。
- 锚点定完后，其相对位置不再为了「更省地方」随意平移；要挪就整组刚体平移。

## G3 归属：两脚件依附于赋予它功能的引脚 **[审阅]**

每个两脚件归属于**赋予它功能的那一个引脚**，而不是最近的空闲空间：

| 器件 | 归属引脚 | 摆法 |
| --- | --- | --- |
| 上拉/下拉 | 开漏输出、复位、片选、I²C 脚 | 离该脚 ≤3g，竖直引向对应轨 |
| 去耦电容 | 被去耦的电源脚 | 贴脚，电源符号朝上、GND 朝下 |
| 栅极电阻 | 栅极 | 串在栅极出线轴上 |
| 限流电阻 | LED/光耦输入端 | 串在路径轴上，不绕行 |
| TVS/钳位 | 被保护引脚 | 从节点竖直引向地 |
| 反馈分压 | 反馈脚 | 竖直叠放，抽头侧向引出 |

归属判错的典型症状：器件整齐排列在页边，读者必须沿着标签跳回引脚才知道它属于谁。

## G4 画法角色表 **[检查]+[审阅]**

每个支路先选角色，再套模板；不要「看到两个脚就随便拉一根」。

| 角色 | 何时用 | 几何模板 | 必检 |
| --- | --- | --- | --- |
| `series` | 串联限流/分压/滤波 | 沿路径轴一进一出；引脚出线 ≥2g 后进器件；同轴，不绕行 | 无多余拐弯、两端 ≤2 折 |
| `shunt` | 对地/对轨旁路 | 从节点竖直引向轨：GND 向下、正电源向上；负电源轨在其地线下侧 | 竖直、不横穿其它支路 |
| `bank` | 并联组（去耦阵列、多个 LED 并流） | 共用一条平直轨，器件正立同向、间距一致（2–4g） | 轨平直、无交替绕行 |
| `divider` | 反馈/基准分压 | 竖直叠放，抽头从中间节点侧向引出 2g 再接标签/负载 | 抽头不压在器件上 |
| `decoupling` | 电源去耦 | 贴电源脚 ≤3g，电源上/GND 下，最短直连 | 不得跨块、不得用标签代替 |
| `lane_*` | 重复通道（多路相同接口） | 所有通道同一模板、同一相对坐标，只改绝对偏移 | 通道间画法完全一致 |
| `rail` | 页级电源/地轨 | 横或竖一条直线；标签只放轨端或引出点 | 轨中间不乱挂标签 |

## G5 引脚出线 **[检查]**

- 每条支路**先沿引脚向外**走 ≥2g，再拐弯；贴着器件边缘立即转 90° 会把引脚和线糊在一起。
- 绕行从块上方/下方过，**绝不穿过另一条支路**；两段同网导线不要共线重叠（原生合并会静默短路）。
- 折弯数控制：两端连接的网络 ≤2 折（默认阈值），超过就改画法或拆块，不要靠加标签续命。
- 连接状态必须明确：T 形分支落 junction；未连接的交叉必须正交、且离端点/拐角/交汇点 ≥2g。
- 引脚出线方向错误（首段背离引脚朝向）由 `circuit_audit.py` 判；`readability_audit.py` 另报 `short-pin-exit`。

## G6 电源轨与标签语义 **[检查]+[审阅]**

- 电源符号（netflag）用于**轨道**；全局标签只用于**出页**网络；页内小网络名只标**选定**的网。
- 局部 label 只在有边界理由时用（跨块、避开长线）；**绝不用标签掩盖走不通的线**。
- 每个标签只有一个角色（电源/地/出页/页内）。同一页出现两种角色混用，读者无法区分作用域。
- 地网画法在开工前显式选择（单点/分区/数模分开）并写进交付说明；
  绝不为「好看」合并一次侧/二次侧/机壳/信号/Kelvin 地。
- 电源网允许分散的多符号树（每个符号都有真实短桩），这不等于断网；非电源网的多树必须有标签，
  否则 `net-not-physically-connected`。

## G7 间距与文字 **[检查]**

- 无关平行导线中心距 ≥2g；同网段合并前先确认不会与异网段重叠。
- 文字距导线 1.27mm 起；带网络名的线段要比名字长 2g 以上，避免名字压到拐角。
- 符号、字段、出线通道**一起摆**：文字压线时先移文字或改块排列，不缩短电气长度、不挪引脚。
- 单页「间距豁免」超过 3 处，本身判不通过（不是逐处 justify 就能过）。

## G8 修复顺序 **[审阅]**

出问题时按此顺序改，改完一层再重画再查：

1. 画法方向 / 间隙 / 器件顺序；
2. 锚点位置与朝向；
3. 折行、拆块或分页。

**禁止的掩盖手段**：加标签接续断线、缩短真实型号、隐藏参数、改引脚类型、加 PWR_FLAG、
用「可以接受」的间距豁免堆过门。结构问题只能靠改结构解决。

## HR 条款（改编为 EasyEDA 可操作条目）

- HR-01 局部功能关系保持可见：IC 的分压/定时/补偿/检流/滤波画在引脚旁，不集中到页边。
- HR-02 先立主路径：主干先画通，再挂支路；主干没立就摆外围，必然返工。
- HR-03 并联件共用一条平直轨，不各自绕路。
- HR-04 地网络画法显式选择并记录；四类地不合并不美化。
- HR-05 重复接口通道画法一致（同一模板、同一相对位置）。
- HR-06 长块间网络之前，先保留短直局部路径；能局部直连就不跨页命名。
- HR-07 每种标签只有一个角色；角色混用视为错误。
- HR-08 符号/字段/出线通道一起摆；文字冲突先移文字。
- HR-09 宁要少数清楚拐弯，不要均匀撒弯；不要为了「整齐」统一所有拐弯数。
- HR-10 连接状态明确：带点 T 形分支；未连接交叉正交且远离端点/拐角/交汇点。
- HR-11 页面适配电路：小电路用小图幅/单页，不摊在 A3 上凑版面。

## 坏/好例对（改规则的前置条件）

任何要自动化或写进检查器的画法，必须保留**同一网表**的坏例与好例：

- 好例：`scripts/led_demo.py` 的合成几何（必须 PASS 电气与可读性）。
- 坏例：`tests/test_circuit_audit.py` 的 X 交叉夹具——电气 PASS、可读性必须 FAIL 并点名 `w1xw2@20,10`。
- 新规则若没有任何夹具能触发它，就不算规则，只算愿望。
- 每条失败必须**点名对象与位置**（wire id、交点坐标、引脚），否则无法复核，也无法回归。
