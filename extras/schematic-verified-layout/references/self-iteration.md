# 自迭代：事件 → 归因 → 规则 → 合成测试

本技能的价值不只在「这次画对了」，而在**同一个失败不会出现第二次**。
每次失败（EDA 报错、假失败、静默短路、门不过、图面审阅返工、用户退回、检查器误报/漏报）
都必须留下可复现的记录，并落成一条规则或一个测试。

规则：notice → 定位归因层 → 改规则/工具 → 加合成测试 → 重跑全量 → 记 lessons。
同一会话内完成；跨会话只留「未修项 + 复现方式」，不留口头结论。

## 1. 事件账本

每次落图运行在版本目录下写 `events.jsonl`，一行一个事件：

```json
{"id":"ev-003","date":"2026-11-02","project":"<uuid>","page":"P1","rev":"003",
 "symptom":"两条同网导线共线后自动合并，异网被短接",
 "expected":"异网不得共线重叠","observed":"net GND 与 3V3 同树",
 "evidence":["readback-003.json","gate-003.json"],
 "layer":"contract","rule":"G5 共线重叠禁止","test":"test_redundant_overlap",
 "status":"fixed"}
```

必填：`symptom/expected/observed/evidence/layer/status`；`rule` 指向本技能的具体条款，
`test` 指向能复现它的用例。证据用相对路径，并另记 SHA-256。事件只追加，不改写历史。

## 2. 归因四层（先定位层，再改东西）

| 层 | 症状 | 该改哪里 |
| --- | --- | --- |
| 契约层 contract | 坐标方向、旋转角、长度、作用域、引脚号约定不符 | 文档/数据契约 + 夹具 |
| 工具层 tool | 检查器测错对象、单位换算错、变换漏乘 | 脚本 + 校准对 |
| 流程层 process | 顺序错（先接线后定位）、重载后没重解析窗口、没先保存 | SKILL.md 步骤/硬规则 |
| 画法层 drawing | 交叉、绕行、归属错、标签掩盖、模块被连续线穿透 | 画法语法 + 可读性门 |

- 先把事件归到一层，再动手；不要用「EDA 的限制」解释画法层问题。
- 同一现象反复出现时，向上找层：三次同类假失败 → 流程层；多次单位错 → 契约层。

## 3. 改规则必须附合成测试

- 每个新规则/新修法，配一对**同一网表**的坏例与好例；坏例必须被点名失败位置（对象 + 坐标）。
- 改检查器时两边都要过：坏例仍失败、好例不误报，且全量 `unittest discover` 无回归。
- 新规则若没有任何夹具能触发，就不算规则，只算愿望；不要写进 SKILL.md 冒充门。
- 测试命名带规则意图（`test_redundant_overlap`、`test_label_cannot_bridge`），便于账本反查。

## 4. 检查器先校准，再信结果

- 新增/修改几何变换、单位换算、阈值，先对**已知非对称样本**标定（如 LED 阳极/阴极、连接器 1 脚）。
- 真实教训：某工程的三个检查器都静默测错了对象——工具「跑通了」不等于「测对了」。
- 每次出报告写清：检查器版本、阈值、输入 SHA-256、哪些数字是**量的**、哪些是**算的/推的**。
- 报告里 `liveVerified:false` 就是 false；离线通过不许升级成现场结论。

## 5. 对抗式只读复核

- 每个阶段末（目标冻结后、候选生成后、落图后）做一次**只读**复核，角色是找茬，不是确认。
- 复核只读，不改文件；发现问题写进账本，由主流程改。
- **终止判据在开始前写好**（读者任务、允许例外、最大轮数），否则会无限循环。
- 复核不通过就改结构，不改计数、不改豁免、不改引脚类型。

## 6. 长任务与等待条件

- 每个等待条件必须能回答：「此刻进程崩溃，我的过滤器会不会输出一行？」
  只看「进程还活着」的等待等于没等待。
- 看门狗覆盖四种终态：有输出、崩溃签名、进程消失、墙钟超时；另设进度速率下限，
  连续 N 秒无新增输出即判卡死。
- 卡死不自动重试；先保存（`sch save` 往往仍可用），再按 [CLI 陷阱](eda-cli-pitfalls.md) 恢复。

## 7. lessons 与未修项

- 每版运行目录写 `lessons.md`：本次事件、根因层、改了什么、下一个 agent 应知道的**实测行为**
  （例如某接口在某版本下必然报某告警、某操作会静默合并）。
- 本次不修的问题写 `ISSUES.md`：现象、复现命令、影响范围、建议修法。
- `lessons.md` 只写被证据支持的事实；猜测标 `HYPOTHESIS`，不要与实测混排。

## 8. 交付时的自检清单

- [ ] 每个失败事件都有账本条目与证据路径；
- [ ] 新规则有坏/好例对，全量测试通过；
- [ ] 检查器做过坏例点名 + 好例不误报校准；
- [ ] 门 A（strict）与门 B 记录都归档，旧版本已作废；
- [ ] 报告区分：量的 / 算的 / 推的；离线 / 现场；已验证 / 未覆盖。
