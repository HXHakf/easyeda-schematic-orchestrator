# 原理图工作流 0.2

## 阶段与退出条件

| 阶段 | 产物 | 退出条件 |
|---|---|---|
| 识别任务与类型 | requirements | MCU 最小系统、MCU+传感器、LDO 或其他功能；未知先澄清类型 |
| 分轮补问/选型 | next_questions、selection_tasks | 用户每轮至多三问；允许“帮我选”；类型相关字段齐备且无 unresolved |
| 设计确认 | contract.json + 中文.md | 默认和假设可见；确实获得该版本的人类确认 |
| 电路计划 | plan、bindings | 物理脚 net/NC、功能归属、准确库身份/型号及原厂依据 |
| 测试页初始放置 | stage.json、journal | 空白页、精确目标、兼容预检、只有本轮器件，失败先回读 |
| 实测与上游布局 | 原始快照、位号/SVG/边界、layout-input、composition | 完整观测、唯一归属、证据哈希一致；调用上游 lib-layout |
| 编译与执行 | queue、bundle、journal | dry-run；保持已有本轮 native ID；执行前基线未变 |
| 复验 | attempt、report、history | 先失效旧结论，再保存、重载、新回读及各规则检查 |
| 交付 | manifest 与工程产物 | 本轮输入/证据完整且未变；缺项如实列出 |

## 正常交互

用户：“我要画原理图。”先问要实现的功能/电路类型。
用户：“画一个5V转3.3V的LDO。”先记输入输出，再问最大负载和型号是否指定；不问 MCU。
用户：“帮我选。”生成选型任务，依据负载、压差、热和稳定性要求查证候选，不把“帮我选”写成型号。
用户：“STM32接一个温湿度传感器。”追问所需功能/精度、MCU/传感器及供电，不默认 BMP280 满足湿度。
用户更改裸片为模块时重新判断上拉；改电路类型时停止使用旧类型专属字段。

确认页展示可理解的功能、型号、供电、接口、候选默认值、边界与验收。
哈希、UUID、文件摘要由 Agent 内部维护，用户无需照抄长串值；确认后不重复问同一版本。

## 授权与能力边界

只方案/预览不写入；开发此工作流可完全离线。自动触发不是自动获准写入。
当前执行仅接受专用空白测试工程及本轮 staged 实例；对已有图纸的修改先只读分析，不自动清理或接管。
其他 EDA 平台沿用用户选择；当前执行适配只有嘉立创，未支持的工具不虚构。

## 当前验证边界

分类、回合更新、计划/确认、模拟 stage→collect→prepare、复验失效和交付证据核验有自动测试。
测量适配输出已被真实上游 lib-layout 接受；materialize、compose 和 apply dry-run 也有离线集成。
十类/十一类快照兼容问题仍阻断当前发布版现场闭环，不能把接口实现或模拟通过写成硬件完成。
