# 工作流深入审查

后续 0.5.0.dev8 已实现下述六项的首版能力，具体入口与边界见 [辅助工具](../../references/workflow-assistance.md)。
按轮次归档、互斥和目录记录接入正常入口，文字恢复、候选比较及补充索引提供显式命令。
下文保留审查时的问题与开发依据。

本次审查基于当前代码、合成回归和已保留的 MCU 验收记录。现场操作维持原记录，本轮采用离线验证。

## 已修复的证据缺口

| 问题 | 复现与影响 | 本次修改 |
|---|---|---|
| 超时回执覆盖 | 两个 adapter 共用证据目录、各自第一次调用超时，原来都写同名文件，只剩后一次返回 | 每次调用分配独立 UUID，正常及超时文件名均使用该标识；固定相同时间的回归仍能保留两份原始输出 |
| 交付遗漏核心项 | 从一份完整通过报告逐项删除检查或回执，原判断只要求剩余内容非空且通过 | 要求 5 项核心检查与 7 个回执全部存在，继续核对严格布尔通过状态、attempt、输入和文件摘要 |

两项都有失败到通过回归。交付规则检查的是结构完整性和当前文件一致性，现有本地证据仍依赖真实工具调用与原始回执。
实现与回归见 [adapter](../../eso/adapter.py)、[交付检查](../../eso/cli.py)、[回归测试](../../tests/test_regressions.py)。

## 优先改进

| 优先级 | 发现与依据 | 建议实现 | 验收方式 |
|---|---|---|---|
| P1 | verify 保留历史报告，但 save/reload/连接及原生检查回执写回固定文件。实际较早的成功报告引用 7 个文件，当前仅 1 个摘要仍匹配 | 每轮 attempt 使用独立证据目录，绑定当轮输入及原始回执，完成后再更新当前状态指针。失败轮也保留已取得的证据 | 连续成功、成功后失败、执行中断三种情况下，旧报告均可独立重新校验；新失败仍撤销当前通过状态 |
| P1 | verify 缺少互斥锁，execute 锁的范围仅为运行目录。多个进程或运行目录可指向同一页，串行操作目前依靠宿主约定 | 为真实写入及保存重开建立目标级互斥，状态发布采用原子替换，并定义进程退出后的恢复行为 | 用模拟并发进程争用同一目标，确认只有一个写入者；不同目标可独立工作；中断后先读现场再恢复 |
| P2 | 商品属性补齐后 DRC 曾通过但目录来源证明丢失，较晚发现导致重建 | 在现有选库阶段输出统一核验记录，展示同料号候选、制造商、MPN、符号、封装、逐脚依据和缺项；绑定变化后自动标出受影响证据 | 通用/完整条目、同料号不同封装、来源证明丢失均有合成案例；现场用原始目录结果验证 |
| P2 | 保存实例的姿态更新重置文字，当前靠宿主恢复实测偏移。重复手写修正容易遗漏或使用过期属性 | 复用 typed attribute-move，提供带原始 owner、Key、expected 和偏移依据的修正预览；使用新鲜状态执行，并接入完整复验 | 属性 ID 重建、公式、null、重复属性、旋转及连接发生变化时正确处理或拒绝；真实样例保存重开通过 |
| P2 | 自动模块布局成功后整页装箱失败，宿主做了多轮源修订。当前固定页面入口已具备，候选选择和失败分类仍分散 | 优先补充布局失败分类和候选比较记录，保留合法基线，复用上游能力。按硬约束、可读性、转折/线长和占地评估有限变体 | 同一输入重跑可复现候选选择和停止原因；通过候选的完整物理连接、文字和整页边界重新验证 |
| P2 | 原生、补充审计和图面报告靠宿主关联，core manifest 仍单列 visual review 未覆盖 | 增加可选的交付证据索引，明确每项检查的对象、范围、输入摘要与结果，分别计算各验证层的完整程度 | 新图配旧报告、缺 NC/模块、缺外部文字、报告摘要变化均应阻断相关层的通过状态 |

P1 历史文件问题已从保留记录确认，独立原始 adapter 回执可能保存在其他私有目录，需逐项核对后才能恢复历史包。
并发项来自代码审查，本轮未制造现场并发。后续实现及验证结果见 [验证记录](../VALIDATION.md)。
相关实现入口为 [Workflow](../../eso/workflow.py)、[放置恢复](../../eso/recovery.py) 和 [DesignBridge](../../eso/bridge.py)。

## 开发顺序与范围

先完成按 attempt 固定证据，再实现目标级互斥和原子状态发布。两者稳定后接入交付索引，
随后处理目录核验记录与文字修正，最后比较布局候选。每一步复用现有数据、typed CLI 和校验器，
在最小可复现问题上增加正反回归。

当前最大的耗时来源包括较晚暴露的身份问题、布局搜索及写后文字修复，尚无完整可比的效率基线。
先记录首次设计、跨工程复用和修改条件的成功/阻断、补参次数、资料整理次数、人工等待与工具耗时，
再判断哪项改进减少了实际重复工作。

严格器件电气依据、严格 v2 生成路径的现场验收、真实缺件恢复正例及完整效率对照仍保留为未完成项。
六个主题及十个绘图规范条目继续使用既有唯一 ID。现有现场经验的操作入口见
[复盘与恢复](../../references/live-recovery.md)。
